# GitHub Discussions Guidelines

QST uses GitHub Discussions for conversation that doesn't fit the "specific, actionable issue" model of GitHub Issues. This file explains what goes where.

## Categories

| Category | Use For |
|---|---|
| **Q&A** | "How do I...", "Why does BB84...", "What's the difference between..." — anything answerable, not necessarily a bug. See `docs/26_PROJECT_GLOSSARY.md` and `docs/22_MATHEMATICAL_FOUNDATION.md` first. |
| **Ideas** | Early-stage feature ideas not yet concrete enough for a formal Feature Request issue. If an idea matures, it should graduate into an issue (using the `feature_request.md` template) or a `docs/20_FUTURE_ENHANCEMENTS.md` entry. |
| **Show and Tell** | Projects, course exercises, or research built using QST — we'd love to see how the toolkit is actually used by students and researchers (per `docs/02_PRODUCT_BLUEPRINT.md` §4 target audience). |
| **General** | Anything else community-related that doesn't fit the above. |

## Issues vs. Discussions

- **Issue:** a specific, actionable bug or feature request with a clear "done" state — see the issue templates for bug reports, feature requests, questions, and documentation issues.
- **Discussion:** open-ended conversation, brainstorming, or support questions without a single clear resolution.

If a Discussion produces a concrete, actionable item (a real bug, a well-specified feature), a maintainer or the original poster should open a corresponding Issue and link back to the Discussion thread.

## Educational Use Welcome

Given QST's educational mission (`docs/00_PROJECT_CONSTITUTION.md` §3), we especially welcome:

- Questions from students working through coursework using QST.
- Instructors sharing how they've incorporated QST into a lab exercise (Show and Tell).
- Research use cases that reveal a gap in Research Mode's current capabilities (Ideas or a linked Feature Request issue).

## Code of Conduct Applies

All Discussions activity is governed by [`CODE_OF_CONDUCT.md`](../CODE_OF_CONDUCT.md), same as issues and PRs.
